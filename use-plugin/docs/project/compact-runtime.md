# Compact runtime mapping

The active `.mrv` descriptors select compact mapping version 3. The compiler reads
the selected `.csl`, `.istar`, optional `.ocl`, XML and official project catalogue.
It does not load the historical long XML, reconstruct its DOM, or select a case
by name or hash. Framework policies are versioned; business names belong to the
authored inputs.

## Responsibilities

| Component | Responsibility |
| --- | --- |
| Source and target catalogues | Resolve actual declarations, signatures, fields and native model symbols. |
| Observation planner | Derive typed capability requests and source checkpoints from admitted correspondences. |
| Native preparation | Install authored classes, conditions, operation signatures and typed observer fields on the candidate USE model. |
| Runtime projection | Apply qualified source cuts through the existing native writer and rollback boundary. |
| Scope projection | Correlate physical players, public roles, scheme identities and actual plan invocations. |
| Task bindings | Bind exact PRE/POST callbacks, demand episodes, source references and operation receipts. |
| Native engine owner | Evaluate original Goal/Task recurrence and native OCL against the authoritative MSystem. |
| Checkpoint service | Return an exact-token decision; retain the producer hold on failure or unavailable evidence. |

## Source identity and initialization

A source invocation can exist before its scheme and business artifact. Its
initial graph contains the observed invocation plans and their native ancestors;
it does not fabricate future organizational actors. A qualified scheme reference
merges that initial invocation into the same execution identity. When the actual
domain and role members become available, the execution topology is rebuilt from
the expanded graph. Only compatible leaf episodes may retain native history.

Execution identity is separate from a physical object alias. The scope can acquire
a group and artifact without redirecting a physical source identity to a different
USE object.

Task references include only resources needed by that Task. An unrelated artifact
appearing in the same execution does not start a new Task episode. A temporarily
unqualified cut cannot certify a Task. A retained selection becomes current again
only when its original scope, player, role lifetime, demand episode and references
are proven again. This reuses its original PRE/POST certificate; it creates none.

## Verification and applicability

Native raw markings, certified execution outcomes and observation quality remain
distinct. Future or unobserved work is not converted into failure or success.
Known absent current demand is carried as assignment evidence, not as Complete.
Selected roots are checked at a settled source scope; authored ANY/ALL policies
remain unchanged. A supporting failed attempt remains in history even when an
authored ANY requirement has another successful witness.

An operational invariant may explicitly declare a role-based activation on its
group correspondence using `activateInvariant`, `activationRole` and
`invariantActivationPolicy="LATCH_ONCE_QUALIFIED/1.0"`. Activation requires a
complete same-cut public roster and native role projection. It is latched per
context incarnation: removing a required role later does not deactivate the check.
The OCL body is never rewritten.

## Observer policies and coverage

Observer fields use typed source policies, not XML table/join programs. Supported
families include actual identity/workspace values, CArtAgO operation histories,
MOISE public state transitions and committed/done players, successful selected
Jason actions, and NPL activation/deadline/terminal evidence. MOISE transition
receipts also require the logical source clock even when a domain deadline
constraint is disabled. Missing history, clock or population proof stays unknown.

Numeric widening is explicit (`JAVA_SCALAR_NUMBER_TO_REAL/1.0`); unsupported,
non-finite or inexact integer values are rejected. Source field and operation
receipts retain their pinned framework class provenance.

## Boundaries

This migration does not replace the platform barrier. JaCaMo still owns operation
admission, draining, asynchronous producers and logical clock suspension. USE
never waits while holding an artifact or Swing lock. Approval and review remain
bound to the exact run, generation, revision, policy, token and snapshot/result
hashes. Manual Continue records review and preserves the original failure.

Unsupported source families, observer tuples or overlapping demand episodes in a
single native Task slot are rejected explicitly. This is not a claim of arbitrary
Java/ASL semantic inference. New policies need framework evidence and focused
tests; they must not introduce a case-specific fallback.

Current executable receipts are indexed in
`verification/compact-completion-20261112` under the plugin root. Service/TCP
acceptance is separate from manual desktop acceptance.
