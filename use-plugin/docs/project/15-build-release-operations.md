# Build, Release and Operations

## Build

Run from the USE repository root:

```powershell
mvn -B -pl use-plugin -am verify
```

The native production artifact is built from the neutral contract, official
JaCaMo adapters and `use-plugin`. JaCaMo dependencies remain on the JaCaMo-side
classpath; the USE plugin does not load those runtime objects directly.

For a package-only build:

```powershell
mvn -B -pl use-plugin -am -DskipTests package
```

The package phase stages the shaded plugin into `use-gui/lib/plugins`. The
release integration tests then exercise the packaged plugin in an isolated USE
runtime, including native export recompilation, Session/OCL loading and GUI
staging.

## Production package contents

The release archive contains:

- the USE plugin JAR and neutral/official Bridge JARs;
- `README.md`, `KNOWN-LIMITATIONS.md`, `docs/architecture.md`,
  `docs/user-workflow.md` and this build/release guide;
- native runtime schemas and the supported example fixture;
- exact release and compatibility metadata.

The archive still carries frozen V1/V2 resources required by the explicit
`LEGACY_V2` compatibility API and its freeze tests. Those resources are
historical compatibility inputs, not the authority used by
`CODE_GROUNDED_NATIVE`; the native branch builds `MModel`/`MSystemState`
directly from the official typed contract.

## Release gates

Before publication, verify:

1. focused native, GUI and generic-launcher tests pass;
2. the complete reactor `verify` passes with no failures, errors or skips;
3. package/release tests pass against the generated archive;
4. native OCL, Session, runtime projection and export tests pass;
5. release checksums and manifest entries match the generated bytes.

No release claim promotes static import, archived evidence, a compatibility
mapping, or a case-study run to live native semantics without exact API and
runtime evidence.
