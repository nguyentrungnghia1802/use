# Source-target mapping and declarative runtime bindings

Status: design, not an implemented or accepted runtime feature.

## Authoring contract

The author supplies a JaCaMo project, a CSL model, an iStar model, optional additional OCL, and an XML correspondence document. Each concept correspondence has `source` and `target` attributes. Two sections distinguish JaCaMo-to-CSL and JaCaMo-to-iStar correspondences. By the user's subsequent clarification, concise declarations of runtime binding, scope, population quantification and selected requirements may remain in XML; moving them into the model languages is not mandatory. This relaxes the previous source-target-only design without permitting handwritten runtime query pipelines.

The project/model inputs are selected by the existing project descriptor/workbench. They are not rediscovered by matching case names. Source and target references are resolved against their parsed, typed models. Missing or ambiguous references are errors.

Illustrative syntax only; the reference grammar and namespace are not implemented:

```xml
<mapping>
  <csl>
    <map source="artifact:auction_env.AuctionArtifact" target="Auction"/>
    <map source="artifact:auction_env.AuctionArtifact/property:winner"
         target="Auction.winner"/>
  </csl>
  <istar>
    <map source="asl:src/agt/auction_capabilities.asl/goal:do_auction/2"
         target="auction_capabilities.do_auction"/>
  </istar>
</mapping>
```

Source references identify types, members, source goals, plans or explicit AST regions. They must not encode joins, algorithms, verdicts or hidden case-specific defaults. Multiple runtime instances of one source type are handled by the engine, not repeated XML entries for business IDs. An iStar model actor is a modeled intentional subject/view, not inherently a runtime occurrence. JCM declarations can name agents before startup, while their actual runtime identities and incarnation-specific evidence must come from the source. A single ASL program can be used by multiple physical agents.

## Ownership of definitions

- CSL owns context/entity/role structure, attributes, links, cardinalities and its authored constraints/contracts.
- iStar owns actors, intentional elements, refinement/dependency/resource relations, Goal temporal types and Task/Goal conditions.
- Concise mapping-layer declarations may retain dependency population quantifiers, selected requirements, activation/episode context and explicit same-source Goal view correspondences. They must reference the authored graph and preserve its conditions and relations; they cannot invent a social Dependency or replace a false condition with success. Changing such declarations is a semantic change, not formatting.
- Runtime variables such as `self`, `step` and named parameters require typed model context and source signature binding. A source-target pair alone cannot resolve an ambiguous runtime receiver.
- Additional OCL remains authored OCL. XML does not contain domain condition bodies or forced success criteria. Population binding/quantification remains declarative and uses the generic engine.
- Source hashes, capability inventories and compiled observation plans are generated by the tool and retained for provenance. They are not handwritten case configuration.

Do not copy the old XML into model comments or a per-case hidden profile. That would relocate rather than remove the authoring burden.

## Processing architecture

1. Parse the actual JCM/ASL/organisation/artifact inputs into a typed source catalogue, retaining source positions and asset digests. Static source validity does not prove runtime population completeness.
2. Compile CSL and iStar with their native frontends. Read authored definitions and conditions from those models and validate the concise XML runtime-binding declarations against them; do not guess semantics from names.
3. Resolve and type-check source-target pairs. The compiler must explain unresolved, incompatible, multiple or conflicting correspondences. Mapping coverage is checked only for elements that require external observation; derived refinements are not required to invent source callbacks.
4. Compile a versioned observation/binding plan using generic source adapters and typed correspondence rules. Generate observation requirements, identity keys, source task partitions, receiver/parameter bindings and provenance. Ambiguous relationships require an explicit source reference or model declaration, not a heuristic join.
5. JaCaMo owns execution, source events and supported checkpoint admission. Collect actual physical identities, source references and lifecycle events. Do not derive artifact truth from console text or an agent's belief.
6. Bind current observations to runtime instances of the admitted source symbols. Scope includes run and qualified source identities; invocation and activation identities are preserved. Initial requests remain represented before creation of a scheme/artifact.
7. Project accepted observations into the existing authoritative MSystem. Evaluate original OCL and native Goal/Task engines. Preserve applicability, data quality and historical evidence independently of current three-valued intentional values.
8. Reuse exact-token authenticated checkpoint decisions and presentation-before-release. Missing evidence, unsupported producers, timeout, disconnect or errors retain the hold. Manual review never repairs a result.

The compiler may produce an internal plan; its rules must be generic and must not look up a prewritten case pipeline by project/model/agent/task names or digests. The plan is generated from the selected sources, the actual models and the source-target pairs.

## Current integration points

- `semantics/mapping/xml/AuthoredModelLoader`: preserve direct CSL/iStar frontend compilation and authored source identity.
- `semantics/mapping/xml/MappingInputs`, `MappingXmlReader`, `MappingVocabulary`, `MappingSpecification`: introduce a separate versioned source-target frontend; do not silently reinterpret v2 replay documents.
- `semantics/mapping/xml/GenericMappingEngine`, `GenericBindingPlan`, `runtime/*`: separate compilation of observation mechanics from authored correspondence data.
- `semantics/runtime/GoalViewRealizations` and population/requirements handling: retain explicit concise XML declarations where needed, preserving existing meaning, native evidence and authored model authority. No model-language extension is required merely to relocate these declarations.
- The bridge collectors and source instrumentation remain responsible for source evidence; extending the mapping format does not establish new barrier guarantees.
- The current worktree contains unrelated Hello World and runtime corrections. Preserve them and assess their diff before integrating changes in shared classes.

## Acceptance gates

All gates are open. This document is not evidence of implementation.

- [ ] Define a typed source-reference grammar and deterministic source resolution, including multiple plans for one trigger and non-overlapping AST task regions.
- [ ] Specify and validate concise runtime-binding declarations alongside source-target correspondences. Preserve existing graphs and conditions; extend model syntax only for an independently justified modeling need.
- [ ] Implement the compact XML reader, rejecting handwritten executable pipelines, forced verdicts and external entities.
- [ ] Implement generic observation-plan compilation; no case-specific templates, hidden legacy XML or name-derived verdict policies.
- [ ] Connect the compiler to Prepare + Import, runtime projection, checkpoints, history and UI using the native models.
- [ ] Migrate affected example bundles; XML contains correspondences and necessary concise runtime bindings only. Recompute generated provenance without weakening source admission.
- [ ] Compare old/new plans on identical frozen source inputs: identities, values, Goal/Task/OCL results, applicability, unknown diagnostics and scopes. Record intended differences separately.
- [ ] Prove case independence with renamed concepts, multiple agents/schemes/workspaces, duplicate display names, setup failure before creation, repeated invocation and incomplete populations.
- [ ] Test actual source task entry/exit/failure, in-flight operation, supported time behavior, stale reply and repeated manual review paths where affected.
- [ ] Build the coherent installed package, verify loaded artifacts and perform bounded live acceptance. Do not run full clean verify or claim all possible cases from finite examples.

## Delivery boundary

The accepted source-target mapping is an authoring interface, not automatic requirements synthesis. New Java APIs or producers may require an adapter; unsupported data is reported explicitly. The engine must not invent domain associations, source causation, quantifiers, receiver context or target satisfaction to accept a mapping.
