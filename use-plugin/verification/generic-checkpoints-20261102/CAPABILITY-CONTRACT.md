# Generic case-study contract

The production path selects capabilities and identities from admitted authored
JCM + mapping XML + CSL + iStar + OCL inputs. It has no table of case names,
agent names, result counts, expected winners or Swing milestone numbers.

## Source and checkpoint boundary

Source admission covers one owned local MAS with the pinned Jason/CArtAgO/NPL/
MOISE providers. Includes resolve with the actual loader paths. Java clock calls
require identity-checked compiled weaving. Presentation-only Swing callbacks and
the pinned GUIArtifact dispatch cross the supported boundary; unadmitted custom
threads, schedulers, remote/native producers and domain GUI callbacks are rejected.

The versioned checkpoint policy requires admitted Task terminal steps or operation
boundaries. Merely having a valid static mapping does not define source milestones.
At a selected terminal marker admission closes before population capture. Its
existing source permit prevents READY until evidence has been published. Already
admitted operations/notifications drain or yield; the supported logical clock
freezes only when the ledger has no active/pending work. No network/USE wait runs
while a source/artifact/listener lock is held. Publisher, ingress and control live
throughout the hold. An unprovable interval emits GAP and retains the hold.

## Mapping and presentation

Entity resource scopes and explicitly declared project/workspace viewpoints use
the same native MSystem and original Goal/Task/OCL engines. Ownership follows
declared relational joins to exact physical context identities. Shared agent or
field names never imply shared state. Incomplete/ambiguous ownership stays unknown.

Without presentation XML the view projects authored CSL declarations and declared
CLASS observers from the exact frozen cut. Consecutive identical scoped objects,
attributes and links share one visible state milestone. Every verification cut,
failure, source token and native Task transition remains in the audit history.

A complete zero-row observer table has an exact current population certificate:
native universal invariants use their normal empty-set semantics. Existence is
never manufactured, and a newer partial cut revokes the certificate.

## Review, persistence and acceptance limits

Automatic release requires the exact presented token/run/generation/revision,
policy, scope and result/state hashes. Future Goal/Task progress is distinct from
applicable unknown/failed checks. Acknowledgement releases the reviewed cut and
preserves its original failure, state and evidence; later failed tokens remain
independently reviewable. Timeout/disconnect/error/missing evidence keep the hold.

Verified declarative journals use lossless GZIP members under the existing physical
quota. Canonical plaintext exports retain all original hash-chained JSON records;
schema 3.5 declares a bounded decoded replay budget. Corruption, exhausted physical
quota or persistence failure retain the hold. Implementation-incompatible older
replays are rejected, never silently reinterpreted by newer verifier bytes.

Passing the supplied live cases is evidence for these capabilities, not a claim
that unseen arbitrary programs or incomplete mappings have been verified. A new
case must declare its source milestones/requirements and pass the same admission,
mapping and evidence checks. Unsupported capabilities need real hooks/probes;
case-specific fallback code and invented PASS values are not acceptable.
